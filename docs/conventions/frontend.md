# The moderation SPA: the full reference

`frontend/CLAUDE.md` keeps the invariants an agent must not break; this file is the detail it used
to carry — the layout tree, the screen-by-screen behaviour (clusters, references, creators, claims,
overview, originals, candidates), the confidence and availability display, the keyboard map, the
parity measurements and the narrative each rule grew out of. Moved here verbatim on 2026-09-18
(issue #79); nothing was removed. The decisions live in ADRs 0004, 0014, 0015, 0017, 0026 and 0028.

# Frontend conventions

Internal moderation SPA (ADR 0014, on ADR 0004): Vite + React 19 + TypeScript strict, Tailwind v4,
TanStack Router (code-based routes in `src/router.tsx`) and TanStack Query. Node >= 20.19, npm.

**Two customer apps, one of them on its way out.** The customer UI under `/app` (ADR 0026) exists
twice while phase 2 lands: in this SPA, and as a Next.js project in `frontend/customer/`
(ADR 0036), which is what production serves with `CUSTOMER_APP=next`. Conventions for it are at
the bottom of this file. **They share one copy of the words and of the pure logic** —
`src/i18n/{en,de,language}.ts` and `src/app/{apiTypes,caseFile,signInError,rights,invoices,submissions,addOriginal}.ts`
— imported there through `@shared/*`, so a change to either reaches both. `lib/routes.test.ts` in
the Next project fails when this SPA gains an `/app` route the Next app does not have: add the
screen in both, or the migration silently loses it.

## Screen elements
- **Every page row** (clusters, reference queue) shows `AvailabilityBadge`: online / removed / unknown
  plus "checked N h ago" or "never checked" (`availability_checked_at`). Removed pages are dimmed
  (and struck through); both queues have "Hide removed pages" (`?hideRemoved=true`; server-side
  `hide_removed` on reference items, display-only on clusters, where hidden members are excluded
  from bulk Confirm / Reject).
- **Clusters** (`/clusters?show=linked&reference=ID`): default "All clusters" (issue #2, operator
  2026-09-17: most clusters are not linked to an original, so "linked only" as the default showed
  an almost-empty queue), linked clusters first; "Linked to an original only" is an opt-in filter.
  The top of each cluster lists "Linked originals"
  (`linkedOriginalSummary`, best evidence first) or says "Not linked to any original". Member rows
  show their own original links (match strength / leak status) and a provenance line from
  `provenanceLabel`: "Proposed by system — PDQ", "Confirmed — from your pair labels", "Confirmed —
  by you (…)". Provenance is **derived** by the API (no decider is stored); say so in UI copy.
  "What do the statuses mean?" (`StatusLegend`) states that nothing is auto-confirmed.
  Decided members have "Reset to proposed"; the API returns `notes` when `build_clusters` will
  re-confirm (SAME pair label) and the screen shows them as an info toast.
- **Check availability now** (cluster header; per page in the reference queue) only queues crawl
  tasks (`POST /review/clusters/{id}/recheck`, `POST /review/pages/recheck`); the toast says results
  appear after the crawler visits them. Never fetch pages from the browser.
- Toasts: `Flash tone="info"` (`role="status"`); errors keep the default `role="alert"`.

## Confidence display (reference queue, ADR 0015)
- Formatting and filter state live in `lib/confidence.ts` (tested): `bandTone` / `bandClasses`,
  `bandLabel`, `timelineText`, `evidenceNotes`, `signalBreakdown`, `thresholdsText`, and the URL
  filter helpers `parseBands`, `toggleBand`, `cycleBands`.
- Every item with a match shows a **band badge** with the confidence as a percentage: high = green,
  review = amber, low = grey ("high · 76%"). Pairs without a match say "no match · no confidence".
  The queue table has a Band column. `decided_by=auto` rows get a "decided automatically" badge.
- Timeline line: "timeline 0.99 · 6/6 frames in order" (`consistent_frames` / `ordered_frames`,
  the latter parsed by the API from `timeline_reason`) or "no frame order (poster only)" when
  `timeline_score` is null. Null is neutral in scoring; never style it as a penalty.
- Copy extent (issue #62, `lib/copyExtent.ts`): a "Copy extent" line under the timeline
  ("excerpt — page clearly shorter than the original · spans 01:41 (3% of the original)") and a
  badge next to the strength once determined; cluster member links append it via `linkEvidence`
  ("strong match · excerpt"). Every reason code has words (`EXTENT_REASON_CODES`). It never hides
  anything.
- Loose frames (distance 32–40, admitted by timeline or corroboration) and common-frame discounts
  (with their mm:ss moments) are amber notes under the signals. "Why this confidence?" is a
  `<details>` panel listing the API's `confidence_signals` (label, input, contribution, weight),
  the clamped total, the band thresholds from `meta.band_thresholds` and the raw timeline reason.
  Labels and inputs come from the API; do not recompute weights in the browser.
- Order comes from the server: proposed first, band high → review → low (no match last),
  confidence desc. With status "all", a pair decided meanwhile can reappear on a later page; the
  screen keeps each `key` once.
- Filters in the top bar persist in the URL: band chips (`?band=["high"]`, multi; none = high +
  review), "include low" (`?includeLow=true`; low is hidden by default and the screen offers
  "N low-confidence pairs hidden · Include low" from `meta.hidden_low`) and "decided by"
  (`?decidedBy=auto|human`, switches status "proposed" to "all"). `B` cycles the band filter
  (default → high → review → low → default).

## API client
- Change the backend API → `make openapi` → `make frontend-api`. Both files are committed and
  drift-checked. Never hand-write request/response types; alias them from `Schemas[...]`.
- Call endpoints as `unwrap(api.GET("/api/v1/...", { params, body }))`; it throws `ApiError`
  (status, `detail`, body) for non-2xx. `errorMessage()` turns 409 conflict bodies into text.
- Auth is the Django session cookie. `GET /auth/me` sets `csrftoken`; the client middleware sends
  it as `X-CSRFToken` on unsafe methods. A 401 anywhere refetches `me` and shows the login screen.
- Same origin only: relative `/api/...` URLs. No absolute URLs, no third-party hosts.

## Queries
- Queues use `useInfiniteQuery` with the server's keyset cursor, `staleTime: Infinity` and
  `gcTime: 0`: positions stay stable while reviewing; a new visit fetches fresh data.
- Prefetch: fetch the next page when the cursor is within a few items of the end.
- Decisions are optimistic: dispatch `decided` (reducer), send the request, then `settled` with
  the undo payload (ids the server actually changed) or `failed` (reverts, shows the message).
  Undo resets exactly those ids. Invalidate `counts` (and summaries) after writes, not the queue.
- Queue screens remount (React `key`) when their filter changes; state belongs to one queue.

## Keyboard map (`src/lib/keyboard.ts`, shown with `?`)
`Y` confirm · `N` reject · `S`/`→` skip · `←` back · `U` undo · `O` open page (new tab,
`noopener,noreferrer`) · `X` select current (shift-click rows for ranges) · `1`–`9` reference filter,
`0` all · `?` help · `Esc` close dialog / clear selection. With a selection, `Y`/`N` apply to it.
Clusters: `Y`/`N` apply to checked members, or to all proposed members when none is checked.
Keys typed in inputs, and combinations with Ctrl/Meta/Alt, are ignored.

## Privacy rule (hard)
- **Default is privacy mode: no image requests at all.** Load mode is an explicit toggle stored in
  `localStorage` (`marceline.imageMode`); unreadable storage means privacy.
- Images render only through `MediaGrid`, only from `mediaImageUrl(id)` =
  `/api/v1/media/{id}/image` (server-side passthrough). Never put a page or media URL into `src`,
  `srcset`, CSS `url()` or `<video>`. ESLint rejects absolute `src` literals; the build's CSP
  (`img-src 'self'`) blocks the rest.
- Pages with `safety_status` review/blocked: the API sends no media ids (`media_hidden`), and
  `MediaGrid` renders no `<img>` in any mode.
- **Every image lazy-loads** (operator, 2026-09-18): `loading="lazy"`, `decoding="async"` and a box
  the parent sizes, so a queue of a hundred thumbnails fetches only what the reviewer scrolls to and
  nothing reflows. `MediaGrid` already does this; any new image surface must too. It is a privacy
  rule as much as a performance one — each image is a real request through our passthrough, and one
  the media's host can see us make.
- Safety screen is text only: no media components, and page URLs are plain text, not links.
  Its *Safety incidents* section (`screens/SafetyIncidents.tsx`, helpers in
  `lib/incidentReport.ts`) shows the server-rendered hotline draft verbatim in a read-only
  textarea with copy buttons — never rebuild the text in the browser — and records a filed report.
- Page links elsewhere: `target="_blank" rel="noopener noreferrer"`, http(s) only (`safeHref`).
- No external fonts, CDNs or analytics. `<meta name="referrer" content="no-referrer">`.

## Creators to review and refused claims (issue #29 follow-up, operator 2026-09-17)
- `CreatorsScreen` (`/creators`): `catalog.Creator.needs_review` rows — a name a customer typed
  that matched no existing creator by exact name. Each row shows the organisation whose customer
  upload created it, its linked originals count, and similarity suggestions
  (`GET /review/creators`, simple normalised-name matching, suggestions only). Actions: **mark
  reviewed** (a genuinely new creator), **merge into…** (a duplicate identity: moves every
  reference cast link and page link, unions aliases, deletes the source, logged as
  `marceline.CreatorMergeLog`), **add as alias of…** (the typed name is a studio/brand, not a
  person — same move, and the name itself joins the target's aliases). Both moves need an explicit
  target (a suggestion or a creator id) and a confirmation dialog; nothing is automatic.
- `ClaimsScreen` (`/claims`): refused `POST /app/fingerprints` uploads (409 `claim_needs_review`).
  The customer only ever saw one neutral answer; this screen has the reason
  (`owned_by_other` / `unowned_existing` / `hash_overlap`, with its overlap share), the
  organisation and the original(s) touched (`marceline.RefusedClaim`, `GET /review/claims`).
  Status filter open/resolved/dismissed/all; **Resolve…** / **Dismiss…** take an optional staff
  note. Never surfaced to any customer endpoint.

## Overview, originals and source candidates
- `OverviewScreen` (`/`, the start page; the reference queue lives at `/references`): one
  `GET /review/overview` refetched every 60 s: per enabled site
  pages / tasks / media / availability / request budget, scheduler `JobRun`s, open review work
  (safety highlighted, linking to `/safety`) and the M2 numbers. Numbers and small bars only
  (`Bar`, a `role="meter"` div); no chart libraries, CDNs or fonts.
- `OriginalsScreen` (`/originals`, `/originals/$referenceId`): the browser upload panel requires
  an **owner** first (`lib/ownerChoice.ts`: an organisation from `GET /originals/organisations`, or
  explicitly "unassigned"; ADR 0031) — never derived from the signed-in account. Otherwise
  read-only. Pairs link into the
  reference queue with `<Link to="/references" search={{ reference, site, status }}>`. No page URLs, no
  media. Import stays CLI-only: the screen shows the `add_reference` command
  (`addReferenceCommand` in `lib/overviewFormat.ts`).
- `CandidatesScreen` (`/candidates`): list state and keys in `lib/candidateKeyboard.ts`
  (`A` approve · `R` reject · `H` hoster · `I` ignore · `P` back to proposed · `J`/`↓` next ·
  `K`/`↑` previous · `X` select · `?` help · `Esc`). Actions apply to the selection, else the
  current row; decisions are optimistic and revert on error. Moving an approved candidate
  elsewhere undoes the approval and deletes the disabled Site it created; the API refuses (409)
  while that Site is enabled or has crawl data. The list is not refetched after a decision (rows keep their place).
  **No external resources for candidates:** evidence (queries, result URLs, linking pages,
  redirects) is text, never `href`/`src`; only the candidate domain itself is a plain
  `target="_blank" rel="noopener noreferrer"` link for bare hostnames (`domainHref`).
- Helpers with tests: `lib/overviewFormat.ts` (counts, rates, budget tone, ages, shell quoting).

## PDQ hashing (fingerprinting client, issue #29 / ADR 0017)
- `lib/fingerprintClient.ts` (`fingerprintFile`) decodes on the page and hands the Worker
  (`lib/fingerprintWorker.ts`) both the frame hashing **and** the SHA-256 digest of the file, which
  run concurrently; failures carry a `reason` code, an `AbortSignal` interrupts a hung seek, and
  `maxPositions` refuses an over-long video before hashing. Documents are format v3 (`kind: video`).
  Load it only with `import()` (staff and customer screens both do).
- `lib/pdq.ts` is the only entry point: `hashDihedral(rgb, width, height)` and
  `hashDihedralLuma(luma, width, height)` return the 8 dihedral hashes plus quality,
  `toHex`/`fromHex`/`hammingDistance` alongside. Lazy WASM init (no top-level await), no React,
  no DOM — a Web Worker imports it as is.
- `src/wasm/pdq-wasm.js` is Meta's PDQ C++ compiled by `frontend/wasm/pdq/build.sh` (pinned
  `emscripten/emsdk` image, Docker only, output committed so `npm ci` needs no toolchain). It is
  generated: eslint ignores it, tsc sees only the hand-written `pdq-wasm.d.ts`. Rebuild
  instructions and why `-ffp-contract=off` is mandatory: `frontend/wasm/pdq/README.md`.
- **Parity is the contract.** Fixtures live once, in `backend/matching/tests/fixtures/pdq/*.json`
  (generated by `backend/matching/tests/generate_pdq_fixtures.py` from the server's `pdqhash`).
  `src/lib/pdq.test.ts` reads those same files through `import.meta.glob` and requires identical
  hex for all 8 orientations and identical quality; `matching/tests/test_pdq_parity.py` catches
  drift on the Python side. Never weaken either assertion — hashes that differ silently look like
  a matching failure, not a build failure.
- **The decode path is verified in a real browser, not emulated** (`frontend/parity`, issue #28):
  `make browser-parity` runs `fingerprintFile()` in headless Chromium over synthetic ffmpeg clips
  and compares every hash with `matching.fingerprint`. It is **not** part of `make check` (browser
  download, ffmpeg, a minute of decoding). Run it after changing `fingerprintClient.ts`,
  `videoFingerprint.ts` or the WASM hasher. Measured 2026-09-18 on the **current** browser recipe
  (`browser-rgb512-pdq-v1`, Chromium 153, H.264/VP8/VP9): as stored, pooled **median 2 bits, max
  30, 0 of 480 rows past the strict threshold or the loose one**, and `--fail-over 36` exits 0.
  The sampling grids used to disagree — the browser samples `t = k`, the server's ffmpeg `fps`
  filter sampled `t + ~0.47 s` — which put the stored hashes a median of 100 bits apart; issue #70
  fixed that on the **server** (`fps=F:round=up`, tag `ffmpeg-rgb512-pdq-v1`). The tags stay
  separate because the canvas downscale still costs up to 30 bits at 1280×720.
- **`seeked` is not "the picture is on the canvas"** (issue #29, ADR 0022 amendment 2026-09-18).
  Two runs of the harness each showed one sampled position in sixty hashed from the **previous
  second** (60–104 bits, past every threshold, a different clip each run) because `drawImage` drew
  what the compositor still had. `seekTo` waits for `requestVideoFrameCallback` — armed *before*
  the seek, skipping a frame more than 0.25 s early, capped at 250 ms after `seeked` so a seek that
  presents nothing cannot hang. Do not "simplify" it back to awaiting `seeked`; three clean runs
  are what the numbers above rest on. Details in `docs/adr/0022`, `docs/adr/0019` and
  `frontend/parity/README.md`.

## Design system (`src/index.css`, applied 2026-09-18)
- **Tokens only.** `src/index.css` carries the customer app's token set (`frontend/customer/app/
  globals.css`) — same ramps, same type scale, both themes — so a staff screen and a customer
  screen are one product. `src/tokens.test.ts` fails on a raw Tailwind palette class anywhere
  under `src/` except `src/app/**` (the customer rollback copy, pinned to a light ground in
  `CustomerApp.tsx` and going away with ADR 0036).
- **No font files here.** This app has no `public/`, its `/fonts/…` would 404 behind the Caddy
  that serves the customer rollback from this same build, and its audience is one operator over
  Tailscale. It uses the stacks the customer app falls back to; the stylesheet contains no `url()`
  at all, and the test fails on one.
- **`blur-thumb` is ours.** The customer app forbids it (it shows no media); this app is the
  surface the rule was written for. In load mode `MediaGrid` renders thumbnails blurred on a
  `surface-inset` frame with one reveal control per group, re-blurring when the group loses focus
  or the reviewer leaves the page. Privacy mode still makes no request and a safety-flagged page
  still renders no `<img>` in any mode.
- **Radius carries meaning**: evidence is square (`rounded-none` — queue tables, the signals and
  confidence panels, hash and command panes, thumbnail frames), chrome softens (`sm` controls,
  `md` cards, `lg` dialogs), `rounded-full` only for pills, meters and avatars.
- **Automation is violet** (`accent`): a PDQ match, a cluster proposal, a `decided_by=auto` row, a
  derived copy extent, a job's own note. A human decision is neutral or red. Tones are named for
  meaning in `lib/tones.ts` and `lib/confidence.ts`; never for a hue.
- **Spend the red.** Brand red is the active nav marker, the one primary action, a rejection, and a
  live problem — a page still online is red, a removed one is the teal. Colour never works alone:
  every badge also says its state in words.
- **Selection** is `bg-selection` with a `brand-ink` edge. The focus ring is stated once in
  `index.css` for every focusable element; no component sets its own.
- Staff wording is not customer wording: leak, case, confidence, band and distance are correct
  here. `src/i18n/wording.test.ts` governs the customer strings only.

## Style
- TypeScript strict + `noUncheckedIndexedAccess`; no `any`, no non-null assertions (lint).
- Tailwind utility classes on the tokens above; small shared primitives in `components/ui.tsx`.

- Tests: vitest. Pure logic in `src/lib/*.test.ts` (node); components with

## How the customer words reach a page (issue #99, 2026-09-18)

The rule itself is in `frontend/CLAUDE.md`; this is the full passage, and the rule it replaced.

`src/i18n/{en,de}/core.ts` holds the words every `/app` visit pays for — `language`, `common`,
`nav`, `coverage`, `states`, `overview`, `notFound`, `finding`, `original`, `removals`, `invoices`,
`shell`, `signIn`, `home` — and one slice per heavy screen holds the rest: `caseFile.ts`,
`addOriginal.ts`, `rights.ts`, `notices.ts`. Those four are four fifths of the resource and each
belongs to one route, which is why the SPA used to carry all of them on every visit: one whole
language file, 11.46 KB gzip of a 149.88 KB first load, while the overview names about a sixth of
it. It is 3.86 KB now, and the first load 142.65 KB.

- `en.ts` / `de.ts` **compose** every slice. Everything that wants the whole resource keeps working
  unchanged: `resources.ts` for the tests (key parity, placeholder parity, the wording bans, "every
  key a screen names exists") and the Next app's `requestI18n()`, which renders on the server and
  ships no resource to a browser at all.
- The SPA loads `core.ts` in the `/app` route's TanStack loader (`ensureI18nReady()`) and a screen's
  slice in that screen's own loader (`loadScreenWords("RightsScreen")`). `loadScreenWords` awaits
  `ensureI18nReady()` itself, so it does not matter in which order the router runs the loaders.
  `src/i18n/slices.ts` is the single place that maps a screen to its slices: `router.tsx` loads by
  that map and `src/app/translationKeys.test.ts` checks against it, so a route and its test cannot
  drift apart.
- A language switch loads, for the new language, the core slice plus every slice already asked for,
  then calls `changeLanguage`. `setLanguageForTest` loads all of them, because a test renders
  whichever screen it likes.
- **Three sections are split across `core.ts` and a screen's slice**, because the shell and the
  overview name a few of their keys: `caseFile.where.open` / `.openWarning` (the shared
  `PageAddress` part), `addOriginal.submissions` (the overview's list of uploads being added) and
  `rights.works.missing` / `.blockers` (the overview's rights warning). `en.ts` merges each section
  back together, so **no key path changed and no call site moved**; at runtime
  `addResourceBundle(…, deep, overwrite)` does the same merge. `i18n.test.ts` asserts every key is in
  exactly one slice and that the slices together are exactly the composed resource — a key lost in
  the merge, or defined twice and quietly diverging, is the one thing this shape could get wrong.
- The budget script guards the words on their own line (`CORE_WORDS_BUDGET_KB`, 4.5 KB) and fails if
  anything shipped imports the composed `en.ts` / `de.ts` statically, which would put every screen's
  words back into a chunk and undo the split.

### The rule this replaced, kept verbatim (ADR 0044's exception, 2026-09-18, superseded the same day)

`src/i18n/upload.ts` is deleted and its words are part of the `addOriginal` slice. The paragraph as
`frontend/CLAUDE.md` carried it:

> **One exception, measured:** `src/i18n/upload.ts` holds the words of the upload screen that
> exists only in the Next app (ADR 0044). The SPA ships one whole language file in its `/app`
> first load, so words it can never show cost every visitor bytes — these pushed it over the 150 KB
> guard. The Next app merges the overlay in `requestI18n()`; `src/i18n/resources.ts` merges it the
> same way so key parity, placeholder parity, the wording rules and "every key a screen names
> exists" still cover it. Add a key there **only** when the screen using it exists in the Next app
> alone, and move it back the day the SPA gains the screen.

The layout line that described the resource before it was sliced is still above, in this file's
own layout tree — it was never moved out of it.
